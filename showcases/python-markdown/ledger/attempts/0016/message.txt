Preprocessors: skip regex scanning that cannot match. FencedBlockPreprocessor searched the whole text with the multiline fence regex (tried at every position, about 3 ms for the corpus); now jump with str.find to the next line starting with three backticks or tildes (the only possible match starts). NormalizeWhitespace only runs its blank-line regex (about 3.4 ms, lookbehind at every position) when the text contains a space before a newline. Both exact short-circuits, fenced/whitespace-focused differential fuzz identical.
